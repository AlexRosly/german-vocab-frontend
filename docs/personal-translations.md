# Личные переводы и языки содержимого

Реализовано 03.11.2026. Интерфейс остаётся ru/de/en/uk; переводы слов и примеров поддерживают ru/de/en/uk/pl/tr/ar/fr/es/it/pt. Каталоги UI и содержимого независимы. Новые языки не означают автоматическое заполнение переводов всей библиотеки.

В личном словаре кнопка «Мой перевод» открывает отдельное окно для текущего языка перевода. Сначала выберите нужный язык в верхнем переключателе. Личный перевод виден только владельцу, помечен в словаре и используется в тренировках, прогрессе и просмотре истории. Формула показа: личный текст выбранного языка → общий текст того же языка → «Перевод отсутствует». Русской подстановки нет. Библиотека, обычный просмотр общей карточки, связанные слова, редактор общих переводов и модерация показывают общие материалы. Личные переводы примеров и отправка своего текста на общую модерацию в этот этап не входят.

## API и хранение

GET/PUT `/api/v1/words/:id/personal-translations/:language`, AuthGuard, Cache-Control: no-store. PUT принимает только `{ text, revision }`: NFC, нормализация переводов строк, trim; до 1000 Unicode-символов. Ответ `{ wordId, language, text, revision }`. Для отсутствующей записи text/revision равны null. Пустой текст удаляет только личный перевод этого языка. Revision берётся из GET/последней подтверждённой записи; конфликт — 409, старая запись не перезаписывается. Автоматического повторения записи при 5xx нет. После ошибки редактор сохраняет черновик и блокирует новую запись до явного перечитывания; перед перечитыванием можно скопировать черновик.

Отдельная таблица PersonalWordTranslation / personal_word_translations с ключом (userId, wordId, language), текстом и revision. Требуются активная собственная UserWord и видимость опубликованного либо своего слова; ADMIN не обходит это условие. При удалении слова из личного словаря текст сохраняется, но доступ закрывается; при повторном добавлении доступ восстанавливается. Общая карточка, legacy Word.translation, общие переводы, публикация, связи, прогресс и интервалы SRS не изменяются.

`/words/mine` и учебные ответы добавляют выбранный личный перевод одним пакетным чтением на список карточек, строго по пользователю, языку и текущей видимости. В selectedTranslation добавляется source: personal только для личного текста. Полный набор чужих/своих приватных переводов в Word не вкладывается. История сохраняет ответы/статистику; отображаемый перевод актуален на момент чтения и требует текущего доступа к личному словарю.

## Проверки и выкладка

Backend: words 59, languages 39, study 54, moderation 38, auth 28; build прошёл. Frontend: 113 client-тестов, lint/build; браузерные сценарии с mock API: два аккаунта, независимость PL/EN, личный перевод в тренировке, очистка с возвратом общего, 409 и 500 без потери черновика, ручное перечитывание, мобильный экран 390×844 и арабский текст справа налево. Настоящий Safari/iPhone в этой проверке не использовался.

Миграция 20261103120000_add_personal_word_translations применена только к согласованной демо-ветке «миграцион». Количества и контрольные суммы всех проверенных существующих таблиц до/после совпали; новая таблица пустая. Дополнительно настоящий PostgreSQL проверен во временной полностью откатанной транзакции: изоляция пользователей, stale revision, возврат общего текста и запрет после unlink. Конкурентные PostgreSQL-транзакции этой проверкой не моделировались.

Выкладка: сначала backend с новой Prisma-моделью, затем frontend. Для демо миграция уже выполнена; повторно применять вручную не нужно. На других базах нужен штатный prisma migrate deploy до запуска кода. Публичная работа новой версии на Render пока не подтверждена.
