# Модерация во frontend

Вкладка «Модерация» доступна в dashboard только при текущей роли ADMIN.
Все запросы идут через общий apiClient; окончательный доступ проверяют AuthGuard,
AdminGuard и ModerationService на backend. Назначения ролей через этот экран нет.

- По умолчанию открыта очередь PENDING_REVIEW. Доступны также PUBLISHED и REJECTED.
- Просмотр GET `/moderation/words/:id` показывает форму слова, все переводы и примеры,
  фиксируя серверную revision. Переводы карточки перечислены с кодами языков;
  язык показа обычных учебных карточек не скрывает материалы от администратора.
- Публикация, отклонение, снятие с публикации и возврат на проверку имеют отдельное
  подтверждение в интерфейсе. PATCH `/:id/status` отправляет только publicationStatus
  и expectedRevision просмотренной карточки. Данные автора, роли и переводы не переписываются.
- После решения обновляются очередь, личный словарь и учебные счётчики. Сохранённый
  результат прошлой тренировки на экране очищается, серверная история остаётся.
- Во время незавершённой тренировки или несохранённых результатов решения недоступны.
  Во время записи нельзя переключать вкладки, фильтр или язык перевода.
- При 409 STALE_REVIEW старое решение блокируется. Нужно нажать «Открыть актуальную
  карточку», перечитать изменения и явно выбрать новое решение. Автоматической публикации
  с новой revision нет. Такое же повторное чтение требуется при неоднозначной сетевой ошибке.
- При DUPLICATE_WORD отображается сообщение сервера и доступен просмотр существующей
  карточки; автоматического объединения или переноса личных связей нет.
- Ошибки очереди/деталей можно повторить отдельно. Запоздалые чтения отменяются и
  не заменяют другой выбранный фильтр или карточку. Изменения не повторяются на 5xx.

Проверки: `npm run test:client`, `npm run lint`, `npm run build`; браузерные сценарии
сначала выполняются на временном mock API. Это не проверка настоящей SQL-изоляции.
Для живой проверки нужен backend с прежней auth-миграцией и отдельно назначенный
аккаунт ADMIN. Код экрана не применяет миграции и не меняет роли в Neon.

## Большая очередь

Локальный поиск просматривает немецкую форму и артикль, все сохранённые переводы, множественное число и общую заметку выбранной очереди. Фильтр урока действует вместе с поиском. Личные заметки не используются. На странице показано до 30 карточек; поиск работает по всей полученной очереди. Страницы не являются серверной cursor-пагинацией.

В просмотре есть переход к предыдущей/следующей карточке, в том числе через границу страниц. В подтверждении можно выбрать «Подтвердить и открыть следующую». Решение применяется только к просмотренной карточке с её revision; для следующей снова нужны просмотр и подтверждение. Поиск, урок, страница или статус сбрасывают прежнее подтверждение. Ошибка записи оставляет текущую карточку и требует актуального чтения, перехода дальше не происходит.

Миграций и изменений backend-контракта не требуется. Достаточно Manual Deploy frontend. Успешно записанное решение не объявляется неуспешным из-за последующей ошибки обновления dashboard.

## Окно проверки и редактирование связей — 03.11.2026

Карточка открывается в модальном dialog поверх очереди независимо от положения выбранного слова. Окно имеет собственную прокрутку и постоянно доступную кнопку закрытия. Фон заблокирован для ввода; Escape закрывает просмотр, кроме времени записи. После закрытия фокус возвращается к выбранному слову без прокрутки страницы; если его уже нет, к поиску.

«Редактировать связи» загружает карточки всех трёх статусов и текущие связи. Поиск работает по немецкому слову, артиклю и всем переводам; выводит до 10 совпадений, исключает саму карточку и уже связанные слова. PUT/DELETE `/words/:id/relations/:relatedId` меняют одну двустороннюю связь. Удаление связи не удаляет слова, личный словарь или прогресс. Backend проверяет ADMIN и видимость связанных карточек при чтении. Редактор не является механизмом объединения дублей или утверждения точной синонимии.

Пока редактор открыт, решения, переходы и редактор переводов недоступны. Во время записи нельзя закрыть окно. После ошибки записи требуется явное «Обновить связи»; автоматического повторения на 5xx нет. Подтверждённая запись и последующий неуспешный GET показаны отдельно. Общая revision карточки не меняется API связей.

Проверено локально: 108 client-тестов, lint и production build. Браузер с mock API: поиск по украинскому переводу, открытие поздней карточки при прокрученной странице, переход через границу страницы, публикация только одной карточки и открытие следующей, возврат фокуса, добавление/обратное чтение/удаление связи, блокировка после 500 и ручное обновление, совместимость с редактором переводов. Узкий экран 390×844 проверен в эмуляции, не на настоящем Safari/iPhone. Реальная демо-БД проверялась отдельно только для группы Lohn/Gehalt/Bezahlung/Vergütung.

## Подтверждение без прокрутки

При выборе публикации, отклонения или возврата на проверку открывается компактный модальный alertdialog поверх окна карточки. Он показывает слово, последствия решения и кнопки подтверждения, подтверждения с переходом к следующей карточке (если она есть) и отмены. Первоначальный фокус — на отмене. Escape отменяет только подтверждение, сохраняя карточку и её прокрутку; во время записи отмена заблокирована. Закрытие возвращает фокус к вызвавшей кнопке. Правила revision и ручного повторного чтения после ошибки сохранены.

Проверки этого изменения: 108 client-тестов, lint и production build прошли. В браузере с mock API проверены desktop и 390×844, начальный фокус на отмене, Escape с сохранением прокрутки и фокуса родительской карточки, отмена отклонения, успешное подтверждение с переходом и ошибка 500 без перехода. Записи в настоящую БД при этой проверке не выполнялись.
