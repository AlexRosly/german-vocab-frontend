# Данные и аккаунт

[Единый контракт](https://github.com/AlexRosly/german-vocab-backend/blob/main/docs/data-controls.md).

Настройки → «Удалить аккаунт»; восстановление — отдельный режим формы входа. Настройки ADMIN → «Журнал общих изменений». Публичные /privacy, /terms, /contact доступны без входа. Кнопка обратимо отключает доступ и сохраняет данные для восстановления; это явно поясняется перед подтверждением. Полное стирание данных остаётся запросом на email. Адрес для полноценного Impressum пока отложен владельцем.

## Название действия — 25.11.2026

По просьбе владельца пользовательская кнопка называется «Удалить аккаунт», восстановление — «Восстановить аккаунт». В панели и подтверждении прямо сказано, что доступ отключается на всех устройствах, данные сохраняются для восстановления; полное стирание персональных данных остаётся отдельным запросом оператору. /privacy и /terms описывают это же поведение. Личный архив слов не переименован.

Ввод подтверждения в UI — DELETE. На сервер по прежнему контракту отправляется confirmation=ARCHIVE; endpoint, Google purpose, удаление сессий, хранение данных и восстановление не меняются. Старые серверные сообщения об архивированном аккаунте отображаются как отключённый доступ на всех четырёх языках интерфейса. Миграция и обновление VPS не требуются.

Проверено: 255 клиентских проверок, lint и чистая production-сборка прошли. Локальный браузерный стенд проверил DELETE-gate, сохранение API confirmation=ARCHIVE, парольный путь и имитацию Google с восстановлением прежнего синтетического словаря. Проверены новый текст серверного отказа и RU/DE на 390/320 пикселях без горизонтального переполнения. Реальный Google SDK восстановлен перед production-сборкой; реальные аккаунты и БД не изменялись. Временные серверы 4490/4491 остановлены.
