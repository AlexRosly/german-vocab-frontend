# Просроченные повторения

Добавлено 20.11.2026 только во frontend, без миграций/backend/env/изменения SRS. В блоке «Пора повторить» отдельная кнопка «Повторить просроченные». Просроченным считается срок nextReviewAt **до сегодняшнего календарного дня в часовом поясе аккаунта**, а не просто раньше текущего времени. Сроки сегодняшнего дня входят в общую очередь «Пора повторить». На кнопке показано число подходящих слов.

Используются существующие личные /study/due и /study/progress. Из первой берутся только id/срок, из текущего словаря — сама карточка с личными переводами. Учитываются текущие поиск/книга/урок/уровень/артикль/раздел и допустимость выбранного режима. Архив исключается. Очередь идёт от самого давнего срока, с устойчивым порядком по id при равенстве. Неизвестная дата/отсутствующие метаданные не делают карточку просроченной; без валидного часового пояса запуск заблокирован.

Перед стартом /study/due запрашивается снова: если сроки уже изменились, пустая очередь сообщает об этом и не запускает тренировку. При ошибке запроса нет запуска по старому списку, показан повтор загрузки. Экран пересчитывает календарный день раз в минуту и при возвращении на вкладку. Ответы и сохранение — прежние общие, ручная отметка «Трудное» не меняется. Дневные лимиты и новая аналитика здесь не реализованы.

218 клиентских тестов, lint, production build прошли на чистой отдельной Git-копии. Проверены полночь Europe/Berlin, переходы летнего времени, разные часовые пояса, отсутствующие/ошибочные даты, порядок/дубли, личные данные, фильтры/архив/режим, обновлённый пустой список. Существующее предупреждение autoprefixer в verb-catalog.module.css не относится к изменению.

Браузер только на синтетическом API: поиск сужает 2→1, plural запускает Haus затем Baum, результаты KNOWN/NEEDS_REVIEW сохранены одним запросом. Обновившиеся сроки дают 0 и не запускают старую очередь; HTTP503 показывает повтор и не запускает тренировку; успешный повтор восстанавливает список. RU/DE, ширины 390/320 без горизонтального скролла. Рабочая Neon не читалась и не менялась для этого этапа; публичная приёмка ожидается после Netlify. VPS обновлять для этого frontend-изменения не требуется.
