# Google-вход

08.11.2026: добавлена официальная GIS-кнопка на форме входа/регистрации и явная
привязка существующего аккаунта в Настройках. На Render Google включён; владелец
подтвердил настоящую привязку, выход и повторный Google-вход с сохранением ADMIN
и785 слов. Чтением БД проверены тот же userId и обе привязки EMAIL/GOOGLE.
Отдельный новый Google-пользователь на Render ещё не проверен вручную.

Backend отдаёт публичные настройки через GET /auth/google/config. Пока
GOOGLE_AUTH_ENABLED не равен true или Client ID не настроен, кнопка входа скрыта,
в Настройках показано, что функция пока не настроена. Client ID не вшит в сборку
frontend, Client Secret не используется. Выкладывать backend до frontend.

При поэтапной выкладке старый backend может отвечать 404 на Google config: клиент
считает функцию пока недоступной и оставляет обычный вход. 401/403/5xx при чтении
конфигурации остаются видимыми ошибками с повторной попыткой; сессию они не сбрасывают.

Frontend загружает официальный https://accounts.google.com/gsi/client, получает
одноразовый nonce backend и передаёт callback credential через существующий
apiClient. Окно Google отменяется самим пользователем; email-форма остаётся
доступной. При сетевой ошибке или просроченном nonce есть повторная попытка,
которая получает новый challenge. На время отправки повторные действия блокируются.

Существующему пользователю: войти паролем → Настройки → Вход через Google →
подтвердить текущий пароль → Подключить Google → выбрать аккаунт. Затем можно
выйти и входить кнопкой Google. Словарь/роль/прогресс относятся к тому же userId.
Автоматического объединения по совпадению email нет. Неправильный пароль при
привязке не завершает текущий вход. Пароль и Google credential не сохраняются
в браузерном хранилище; после успеха поле пароля очищается.

При первом Google-входе нового пользователя создаётся обычный USER. Существующие
настройки языка не перезаписываются при повторном входе. Отвязка Google,
восстановление пароля и изменение email остаются отдельными задачами.

В next.config.ts добавлен Cross-Origin-Opener-Policy: same-origin-allow-popups
для страницы входа. Сохраняется same-origin API proxy и существующая HttpOnly
refresh cookie. В Google Cloud Authorized JavaScript origins нужен точный origin
frontend: сейчас https://german-vocab-frontend.onrender.com, после переноса —
также новый Netlify origin. Redirect URI/Client Secret для GIS popup не нужны.

Проверки: 143 client-теста, ESLint и production build прошли. В локальном браузере
с mock API проверены настоящая GIS-кнопка, обычный email-вход рядом с ней, форма
привязки, сообщение о недоступности сервиса с сохранением входа и выход. При 320 px
кнопка помещается без горизонтального скролла. Подпись Google ID token в серверных
тестах и persistence подменены. Отдельно владелец подтвердил настоящий вход и
привязку на Render с сохранением своего ADMIN и словаря.

После серверной миграции и включения проверить именно на Render: привязка старого
ADMIN и последующий Google-вход с сохранением словаря/роли; новый отдельный USER;
перезагрузка с восстановлением cookie, выход, отказ/повторная попытка. В разработке
для реального OAuth добавить конкретный localhost origin в Google Cloud; локальная
проверка кнопки не доказывает разрешённость OAuth для этого origin.
