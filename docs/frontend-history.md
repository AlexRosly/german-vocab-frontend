# Экран истории тренировок

01.11.2026. Вкладка «История» показывает только сохранённые тренировки текущего
аккаунта: дату сохранения, число слов, KNOWN/NEEDS_REVIEW, отдельные ответы с
фильтрами. Новая успешно сохранённая тренировка появляется первой. Обновление
истории не запускает тренировку и не меняет прогресс.

UI переведён на ru/de/en/uk. Даты форматируются по языку интерфейса в часовом
поясе браузера. Язык карточек независим: selectedTranslation берётся из API,
отсутствие выбранного перевода показывается явно без подстановки RU.

Список загружается по 20 записей через GET /study/history, следующие страницы —
кнопкой «Загрузить ещё». Детали запрашиваются при раскрытии одной записи через
GET /study/history/:id. Ошибка следующей страницы сохраняет загруженные записи
и допускает ручной повтор. Есть пустое состояние, загрузка, обновление и ошибки.
Типизированный клиент проверяет даты, счётчики, курсор, владельца, язык и ответы.
Отмена/поколение запроса защищают от поздних ответов после смены аккаунта или языка.
Переключение только языка UI сохраняет открытые детали и выбранный фильтр.

Удаление личной связи не уничтожает тренировку. Сейчас недоступные приватные
карточки скрываются сервером; UI объясняет расхождение деталей с сохранёнными
итогами. Ответы относятся к тренировке, а формы/переводы карточек — текущие.
Длительность и реальное время начала не показываются: модель хранит даты записи
при сохранении. Даже ADMIN не получает чужую историю.

Проверки: 74 client-теста, lint, production build; backend test:study 43,
test:languages 34. Браузерные сценарии выполнены только на localhost с mock API:
20+4 записи, ошибка следующей страницы и повтор, фильтры, смена UI/языка карточек,
отсутствующий UK-перевод, скрытая приватная карточка, новая тренировка первой,
смена аккаунта и отдельная история ADMIN. Реальный Render/Neon не проверялся.

Выкладка при выключенном Auto-Deploy: сначала Manual Deploy backend main,
затем frontend main. Миграция БД для этой фичи не нужна. После выкладки проверить
свою историю и сохранение новой тренировки на настоящем API.

Следующий отдельный этап — профиль/часовой пояс и сохраняемая ежедневная цель.
Они потребуют собственного контракта и миграции; текущий алгоритм SRS не менялся.
