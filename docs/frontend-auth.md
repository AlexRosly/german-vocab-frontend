# Вход и защищённые запросы frontend

Регистрация, вход, восстановление сессии, выход и подключение существующего
интерфейса к персональному API. Общая библиотека и выбор языка перевода описаны
в `frontend-library.md`, административная модерация — в `frontend-moderation.md`.
Полный перевод интерфейса остаётся отдельным этапом. Существующий dashboard
сохранён и доработан точечно.

## Запуск и проверки

Backend должен иметь применённую на тестовой ветке миграцию auth_sessions.
Эта работа не применяет миграции и не меняет DATABASE_URL. Нельзя применять
миграцию к основной базе без отдельного подтверждения.

Frontend: NEXT_PUBLIC_API_URL по умолчанию http://localhost:3001/api/v1.
На backend FRONTEND_ORIGIN должен точно совпадать с origin frontend, например
http://localhost:3000, без завершающего слеша. Для production нужны HTTPS и
NODE_ENV=production на backend. Refresh cookie HttpOnly, SameSite=Lax предполагает
размещение frontend и API на одном site. Поддомены одного домена подходят;
разные site требуют отдельной схемы размещения/настройки cookie.

Из папки frontend, Node.js 22:

```powershell
npm run test:client
node node_modules/typescript/bin/tsc --noEmit --incremental false
npm run lint
npm run build
npm run dev
```

test:client использует встроенный Node test runner и экспериментальное удаление
типов TypeScript из Node 22. Предупреждения этого режима не означают провал тестов.
Новые зависимости не устанавливаются. Next.js остаётся 15.5.28. Конфигурация
ESLint приведена к FlatCompat, подходящему Next 15, без отключения проверок:
[документация Next.js 15](https://nextjs.org/docs/15/pages/api-reference/config/eslint).

## Сессия и запросы

src/lib/api-client.ts хранит access token только в памяти экземпляра клиента.
Токены не пишутся в localStorage, sessionStorage, URL или доступные JavaScript
cookie. Refresh cookie устанавливает и читает только backend; запросы отправляются
с credentials: include. Начальное восстановление использует POST /auth/refresh.
До успешного входа dashboard не монтируется и личные запросы не отправляются.

При 401 один общий Promise обновляет сессию для параллельных запросов. Более
поздний 401 использует уже полученный новый токен. Защищённый запрос повторяется
не более одного раза; для сетевых ошибок и 5xx автоматического повторения записи
нет. Окончательный 401 очищает пользователя и возвращает экран входа. Временная
ошибка подключения при восстановлении предлагает повторить подключение.

Вход, обновление и выход выполняются последовательно, поэтому поздний refresh
не восстанавливает завершённую сессию и не перезаписывает новый вход. Там, где
браузер поддерживает Web Locks, операции авторизации координируются и между
вкладками. Без Web Locks сериализация гарантирована внутри вкладки. BroadcastChannel
сообщает другим вкладкам только о смене сессии, без передачи токенов; они очищают
личный экран и возвращаются ко входу. Можно перезагрузить вкладку для восстановления
актуальной cookie-сессии.

Если выход на сервере не подтверждён, аккаунт остаётся на экране с ошибкой и
кнопкой повторного выхода: UI не сообщает о завершении серверной сессии.
Смена пользователя перемонтирует dashboard по user.id, очищая слова, примеры,
формы, статистику и текущую тренировку. Запросы прежней сессии не повторяются
от имени нового пользователя; просроченные ответы отбрасываются.

## Словарь и обучение

Все запросы существующего dashboard используют apiFetch с Bearer. Рабочий список
получает /words/mine, а не общую библиотеку; тренировка использует только личные
слова. Создание возвращает личную карточку PENDING_REVIEW, что видно по подписи.
Удаление использует DELETE /words/:id/dictionary и убирает только личную связь.

Кнопки редактирования слов и примеров показываются автору неопубликованной
карточки или администратору. Пользователь может читать и слушать опубликованные
карточки, но не получает ложного обещания их отредактировать.

Для чтения показывается selectedTranslation.text, а при null — «Перевод отсутствует».
Русское поле translation сохраняется для формы создания/редактирования, которая
явно подписана «Перевод на русский». Дополнительные переводы и выбор языка UI
будут подключены отдельно. Примеры остаются с существующим русским переводом.

Тренировка получает crypto.randomUUID() как Idempotency-Key при старте. Тот же
ключ сохраняется при обновлении access token и при ручной кнопке повторного
сохранения, поэтому один результат не учитывается дважды. Новая тренировка
получает новый ключ. Сессия ограничена 500 словами согласно контракту backend.
Интервалы и серверные расчёты прогресса не меняются.

## Границы проверок

Автотесты проверяют API-клиент с подменой fetch: гонки 401, очередь refresh/logout,
смену пользователя, сохранение заголовков и ключа сессии, отказы и отсутствие
повторной записи при 5xx. Отдельно проверяются права отображения и переводы.
Браузерная проверка выполнена на отдельном локальном mock API: проверены вход,
ошибка пароля, восстановление после перезагрузки, регистрация второго пользователя,
изоляция словаря, создание карточки и примера, ответы «Знаю»/«Повторить», сохранение,
статистика, удаление личной связи, обновление счётчика новых слов и выход.
Во время активной или несохранённой тренировки удаление слова недоступно;
после удаления карточки устаревшие локальные результаты очищаются.
Эта проверка не заменяет проверку cookie и SQL на настоящей тестовой ветке Neon.
