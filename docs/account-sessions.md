# Активные входы в аккаунт

Раздел «Активные входы» добавлен во вкладку «Настройки» под учебной целью.
Список отмечает текущий вход, показывает даты создания, обновления доступа
и окончания refresh-доступа; другие входы можно завершать по отдельности.
Текущий вход завершается прежней кнопкой «Выйти» вверху страницы. Есть отдельная
кнопка «Выйти на всех устройствах», включая текущий вход. Перед отзывом требуется
подтверждение, которое можно отменить. Текст UI и ошибки переведены на ru/de/en/uk.

Номер «Другой вход» служит подписью строки, а не названием устройства. Устройства,
IP и геолокация не сохраняются; обновление доступа не означает активность человека.
Показаны текущий и максимум 100 других входов; при hasMore есть объяснение.

AccountSessionsClient использует существующий apiFetch, проверяет границы списка,
даты и единственную метку current; выбирает только публичные поля и не сохраняет
credentials. Отмена запросов и размонтирование не допускают позднюю перерисовку.
Ошибка DELETE сохраняет список и подтверждение для ручного повтора. Автоматического
повтора мутаций после 500/сетевой ошибки нет; можно перечитать список после ошибки.

ApiClient.logoutAll использует общую auth-очередь и cross-tab lock, объединяет
одновременные вызовы, останавливает новые запросы и отбрасывает старые ответы.
При 401 bearer может один раз обновиться внутри той же блокировки без вложенного
захвата lock. Другой user.id в ответе refresh не получает logout-all. Только 204
подтверждает отзыв; 500/неверный ответ сохраняют аккаунт для повтора. Повторный
401 завершает локальную авторизацию. Успех очищает токен в памяти и уведомляет
другие вкладки существующим AUTH_MUTATION_EVENT/BroadcastChannel. Поздний refresh
не возвращает старый аккаунт; последующий новый login не стирается старым logout.

Проверки: 90 client-тестов, lint, production build; backend auth 28 и build.
Браузерный localhost mock: три входа Anna, отмена, 500 при отзыве одного и ручной
повтор, RU→DE при открытом подтверждении, 500 logout-all с сохранённым аккаунтом,
успешный повтор и экран входа. После нового login остался один новый вход Anna;
вход другого тестового ADMIN сохранился. Это не тест настоящего Render/Neon.

Выкладка: Manual Deploy backend main, затем frontend main. Миграций и новых env
для этой функции нет. На настоящем аккаунте использовать второй профиль браузера
для второго входа; обычные вкладки одного профиля разделяют cookie. При проверке
«Выйти на всех устройствах» ожидается повторная авторизация во всех профилях.

Восстановление пароля и подтверждение email остаются отдельным этапом. Владелец
подтвердил, что домен и сервис отправки писем пока не подключены. Письма не
отправлялись, фиктивный production-поток восстановления не добавлялся.
