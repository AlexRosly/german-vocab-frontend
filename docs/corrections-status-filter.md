# Исправления: фильтр «Все» — 14.11.2026

Пункт «Все» добавлен в статус предложений для USER и ADMIN. Он показывает OPEN, RESOLVED и REJECTED одним списком с серверной пагинацией. Статус виден на каждой записи, в том числе до открытия диалога. При смене фильтра выбирается первая страница. Первоначальное «Ожидает рассмотрения» сохранено.

Значение ALL существует только для фильтра, не для сохранённого статуса или решения. Клиент принимает смешанные реальные статусы только в режиме ALL; по-прежнему отклоняет неизвестный статус ответа, дубли идентификаторов и несоответствие выбранному конкретному статусу. Области личной истории и общей очереди остаются на разных API-маршрутах. Перевод нового пункта есть на RU/DE/EN/UK.

## Выпуск

Требуется backend с поддержкой status=ALL на `/corrections/mine` и `/moderation/corrections`. Сначала обновить backend на VPS и перезапустить только wortkarten-api, затем использовать новую версию frontend в Netlify. Новых зависимостей и миграций нет.

## Проверено

- Все 158 клиентских тестов, lint и production build frontend прошли.
- Backend: 8 HTTP-тестов исправлений и сборка прошли. Проверены USER/ADMIN, общий total, страницы, сохранение OPEN по умолчанию и отказ записывать ALL как решение.
- В изолированном Next-стенде с копией действующего CorrectionsPanel и синтетическими данными проверены: смешанные статусы, 30+2 личных предложения, переключение страниц, сброс страницы при смене фильтра, 35 записей общей очереди ADMIN, сохранение ALL после решения и новый статус той же записи.
