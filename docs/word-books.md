# Книги в Wortkarten

Общая книга-источник — необязательное поле `Word.sourceBook` до120 символов.
Пользователь задаёт её при создании pending-карточки. После публикации менять
общую карточку может ADMIN, в том числе прямо в модерации. Книга видна всем,
кто имеет доступ к карточке. CEFR и номер урока сохранены независимо от книги.
Книга не входит в критерий дубля: одинаковая карточка из другого учебника
должна добавляться в существующий словарь, а не дублироваться.

Личные книги хранятся отдельно в `personal_word_books`: до20 названий на слово,
каждое до120 символов, с revision для защиты от устаревших изменений. GET/PUT
`/api/v1/words/:id/personal-books` требует авторизацию и доступную карточку именно
в словаре вызывающего пользователя. Даже ADMIN не читает чужие личные привязки.
Они сохраняются при временном удалении из словаря, как личные заметки; без
словарной связи читать/изменять их нельзя. Пустой массив удаляет только личную
привязку. Удаление аккаунта/слова каскадно удаляет данные этой привязки.

Каталог глобальных книг отдельно не создаётся. Источник — название на общей
карточке, личные названия не становятся общей библиотекой и не раскрывают школу
пользователя. Ввод поддерживает подсказки и произвольное новое название.
Заглавные буквы, Unicode NFC и пробелы нормализуются для сравнения/фильтров;
содержание книги не переводится вместе с интерфейсом.

В личном словаре фильтр книги учитывает и общий источник, и личные привязки.
Он применяется ко всем очередям и режимам тренировки. В общей библиотеке фильтр
учитывает только общий источник. Есть варианты «Все книги» и «Без книги».
Сохранение личной книги сразу обновляет локальный фильтр; чужие словари не меняются.

## Выкладка

Миграция `20261108160000_add_word_books` добавляет nullable колонку и отдельную
приватную таблицу в одной SQL-транзакции. Она не удаляет и не заполняет старые
карточки, не меняет языки/примеры/прогресс. Не добавлять migrate deploy в build/start.
Перед push/deploy backend применить только проверенную миграцию с отдельного
согласия владельца: старый backend совместим с добавленными полями, новый backend
требует их наличия. Затем backend → frontend.

Пакет785 восстановленных карточек получает «B1+ Brückenkurs» отдельной операторской
операцией по точному списку ID, после резервной копии и проверки плана. Не выполнять
массовый UPDATE без WHERE и не привязывать дополнительный прежний Apfel автоматически.
Чужие/новые карточки и уже заполненные источники не перезаписывать.

Проверки: HTTP с реальными сервисами и подменённым Prisma — права, приватность,
revision/conflict/очистка, unlink/relink, валидация и дубли; frontend unit/client tests;
локальный браузер с mock API — сохранение личной книги, фильтр и запуск тренировки,
редактор в модерации, библиотека, изоляция второго USER, ширина320px без overflow.
Отдельно: свежая копия16 production-таблиц восстановлена в PGlite0.5.15; миграция и
привязка ровно785 ID проверяются там с сохранением всех прежних значений, FK и CHECK.
Локальная mock-проверка не означает, что экран книг уже выложен на Render.


## Применено к production 08.11.2026

Владелец отдельно разрешил миграцию и push. Применена только указанная миграция,
затем отдельной Serializable-транзакцией источник назначен ровно785 карточкам.
Проверка до/после подтвердила сохранность всех исходных значений, кроме нового
sourceBook. Независимое чтение текущими сервисами:14 миграций,785 личных слов с
источником B1+ Brückenkurs,786 в каталоге, ADMIN и EMAIL/GOOGLE того же пользователя.
Личные книги пусты и недоступны постороннему пользовательскому контексту.

Полная свежая копия17 таблиц после изменения сохранена вне Git. SQL восстановлен
в отдельной PGlite: все17 SHA-256 содержимого совпали, CHECK личных книг восстановлен,
повторное восстановление в непустую БД отклонено без изменений. Автоматическое
ежедневное копирование/внешнее хранилище этим шагом не настраивалось.

После push обновить сервисы Render backend → frontend. Применение схемы и проверка
сервисов на реальной БД не заявляются проверкой нового экрана книг на Render.

## Подсказки 08.11.2026

К исходным B1+ Brückenkurs, A1 Treffpunkt и A1.1 Schritte plus добавлены
A1.2 Schritte plus, A2.1 Schritte plus, A2.2 Schritte plus, B1.1 Schritte plus.
Это подсказки datalist, не закрытый каталог: USER может вписать собственное
название книги при создании pending-карточки. В локальном браузере обычный USER
создал карточку с произвольным источником, и источник появился в его словаре.
